# Архитектура приложения «Battleship»

## 1. Общая концепция

Приложение предназначено для администрирования настольной игры «Морской бой». 

Основные функции:
- Регистрация ходов, совершаемых игроками на реальной доске
- Автоматическая проверка корректности ходов согласно правилам выбранного режима
- Вычисление промежуточных результатов
- Ведение истории партий в JSON-файлах
- Расчёт и хранение рейтингов игроков

Приложение реализовано на Kotlin, взаимодействие с пользователем осуществляется через консольный интерфейс. Данные сохраняются в структурированных текстовых файлах.

<hr style="height:10px">

## 2. Архитектурные слои

Приложение построено по многослойной архитектуре:
- **Domain Layer** – логика игры:
    - Модели предметной области (`Player`, `Board`, `Cell`, `Ship`, `Mine`, `Aircraft`)
    - Правила игры (`RuleSet` и его реализации `StandardRules`, `ExperiencedRules`, `ExtendedRules`)
    - Движок игры (`MoveValidator`, `MoveResult`, `Game`, `Move` и его наследники)
- **Presentation Layer** – консольный интерфейс (`ConsoleUI`, `BoardRenderer`)
- **Data Layer** – работа с файловой системой (`GameDetail`, `GameSummary`, `DataStorage` и его реализация `JsonDataStorage`)

Такое разделение обеспечивает модульность, тестируемость и возможность замены отдельных компонентов (например, смены консольного интерфейса на графический).

## 3. Описание классов

### 3.1. Domain Layer

### 3.1.1 Модели предметной области

### Класс `Game`
Представляет одну партию. Управляет ходом игры, содержит логику переключения ходов, подсчёта выстрелов и завершения.

**Поля:**

| Поле              | Тип                | Описание                                           |
|-------------------|--------------------|----------------------------------------------------|
| `id`              | `Int`              | Уникальный идентификатор партии                    |
| `player1`         | `Player`           | Первый игрок                                       |
| `player2`         | `Player`           | Второй игрок                                       |
| `mode`            | `GameMode`         | Режим игры (`STANDARD`, `EXPERIENCED`, `EXTENDED`) |
| `board1`          | `Board`            | Игровое поле первого игрока                        |
| `board2`          | `Board`            | Игровое поле второго игрока                        |
| `currentPlayer`   | `Player`           | Игрок, который должен сделать ход в данный момент  |
| `moveHistory`     | `List<Move>`       | История всех успешно выполненных ходов             |
| `shotsRemaining`  | `Int`              | Оставшиеся выстрелы текущего игрока                |
| `gameOver`        | `Boolean`          | Флаг завершения игры                               |

**Методы:**

| Метод                                 | Описание                                                                                               |
|---------------------------------------|--------------------------------------------------------------------------------------------------------|
| `start()`                             | Инициализирует количество выстрелов для первого хода                                                   |
| `processMove(move: Move): MoveResult` | Валидирует ход, выполняет его, обновляет очередь хода и оставшиеся выстрелы, проверяет завершение игры |
| `getWinner(): Player?`                | Возвращает победителя или `null`, если игра не завершена                                               |
| `getOpponent(player: Player): Player` | Возвращает соперника указанного игрока                                                                 |
| `getBoard(player: Player): Board`     | Возвращает поле указанного игрока                                                                      |

### Класс `GameMode <<enumeration>>`
Перечисление режимов игры:
- `STANDARD` – классический режим
- `EXPERIENCED` – количество выстрелов равно числу оставшихся кораблей игрока

**Поля:**

| Поле    | Тип                  | Описание                             |
|---------|----------------------|--------------------------------------|
| `cells` | `Array<Array<Cell>>` | Матрица 10×10 клеток                 |

**Методы:**

| Метод                               | Описание                                                         |
|--------------------------------------|------------------------------------------------------------------|
| `getCell(x: Int, y: Int): Cell`      | Возвращает клетку по координатам                                 |

| `isAllShipsSunk(): Boolean`          | Проверяет, потоплены ли все корабли                              |

### Класс `CellState <<enumeration>>`
Перечисление состояний клеток:

- `MINED` – заминирована
- `EXPLODED_MINE` – мина взорвана (попадание по мине)

### 3.1.2. Engine – движок игры и валидация

### Класс `Move`
Абстрактный класс `Move` задаёт общий интерфейс для всех действий игрока.

**Поле:**

**Методы:**

| Метод                                | Описание                                            |
|--------------------------------------|-----------------------------------------------------|
| `validate(game: Game): Boolean`      | Проверяет, допустим ли ход в текущем состоянии игры |

### Конкретные реализации:

### Класс `ShotMove`
Обычный выстрел.

**Поле:**
- `targetCell: Cell` – клетка противника, по которой производится выстрел

### Класс `AircraftMove`
Использование авиации.

**Поля:**

| Поле          | Тип          | Описание                    |
|---------------|--------------|-----------------------------|
| `aircraft`    | `Aircraft`   | Используемый самолёт        |

### Класс `PlaceMineMove`

**Поле:**

### 3.1.3. Rules – правила игры

### Интерфейс `RuleSet`

Инкапсулирует правила, зависящие от режима игры.

**Методы:**

| Метод                                                   | Описание                                                                        |
|--------------------------------------------------------|---------------------------------------------------------------------------------|
| `getShotsCount(board: Board): Int`                      | Возвращает количество выстрелов, которое игрок может сделать за свой ход        |
| `canPlaceMine(board: Board): Boolean`                   | Разрешена ли установка мин                                                      |

### Реализации интерфейса `RuleSet`:
- **`StandardRules`** – `getShotsCount = 1`, мины и авиация запрещены
- **`ExperiencedRules`** – `getShotsCount = количество живых кораблей игрока`, мины и авиация запрещены
- **`ExtendedRules`** – `getShotsCount = 1`, мины разрешены (до 3), авиация разрешена

## 4. Взаимодействие компонентов (стандартный сценарий)

1. Пользователь запускает приложение → `ConsoleUI.start()`
2. Выбирает «Новая игра» → `newGame()`:
   - Выбирает двух игроков из списка (или создаёт новых через `DataStorage`)
   - Выбирает режим (`GameMode`)
   - Создаётся объект `Game`, внутри инициализируются `RuleSet` и `MoveValidator`
3. Фаза расстановки (`placementPhase`):
   - Для каждого игрока по очереди запрашиваются координаты кораблей и вызывается `board.placeShip()`
   - В режиме `EXTENDED` дополнительно запрашивается установка мин (`board.placeMine()`) и выбор самолётов (заполняется `player.aircrafts`)
4. Игровой цикл (`gameLoop`):
   - Отображает поле противника (скрытое) и своё поле (открытое) через `BoardRenderer`
   - Запрашивает команду (например, `shot B5` или `scout C3`)
   - Парсит команду в объект `Move`
   - Вызывает `game.processMove(move)`
   - `Game` передаёт ход в `MoveValidator`, который проверяет его с учётом текущего `RuleSet`
   - При успехе вызывает `move.execute(game)`, изменяя состояние клеток, кораблей, мин
   - При неудаче возвращает `MoveResult.Invalid` с причиной, UI выводит ошибку и ожидает новый ввод
   - Проверяет условие завершения игры
   - Обновляет очередь хода и оставшиеся выстрелы
5. По окончании игры (`finishGame`):
   - Определяет победителя
   - Вызывает `DataStorage.completeGame(game)`, который обновляет рейтинги, историю игроков и сохраняет сводку и детали партии
   - Выводит результат

## 5. Хранение данных
Все данные хранятся в JSON-файлах в рабочей директории приложения:

- `history/players.json` – список игроков
- `history/games.json` – краткая сводка завершённых партий
- `history/games/game_<id>.json` – полные журналы партий
- `history/players/player_<id>.json` – детальная информация об игроке
