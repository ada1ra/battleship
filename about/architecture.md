# Архитектура приложения «Battlehsip»

## 1. Общая концепция

Приложение предназначено для администрирования настольной игры «Морской бой». 

Основные функции:
- Регистрация ходов, совершаемых игроками на реальной доске
- Автоматическая проверка корректности ходов согласно правилам выбранного режима
- Вычисление промежуточных результатов
- Ведение истории партий в текстовых файлах
- Расчёт и хранение рейтингов игроков

Приложение реализовано на Kotlin, взаимодействие с пользователем осуществляется через консольный интерфейс. Данные сохраняются в структурированных текстовых файлах.

<hr style="height:10px">

## 2. Архитектурные слои

Приложение построено по многослойной архитектуре:
- **Domain Layer** – логика игры:
    - Модели предметной области (`Game`, `Player`, `Board`, `Cell`, `Ship`, `Mine`, `Aircraft`, `Move` и его наследники)
    - Правила игры (`RuleSet` и его реализации `StandardRules`, `ExperiencedRules`, `ExtendedRules`)
    - Движок игры (`GameEngine`, `MoveValidator`, `MoveResult`)
- **Presentation Layer** – консольный интерфейс (`ConsoleUI`, `BoardRenderer`)
- **Data Layer** – работа с файловой системой (`PlayerFileData`, `GameFileData`, `GameLogSerializer`)

Такое разделение обеспечивает модульность, тестируемость и возможность замены отдельных компонентов (например, смены консольного интерфейса на графический).

## 3. Описание классов

### 3.1. Domain Layer

### 3.1.1 Модели предметной области

### Класс `Game`
Представляет одну партию.

**Поля:**

| Поле             | Тип                           | Описание                                           |
|------------------|-------------------------------|----------------------------------------------------|
| `id`             | `Int`                         | Уникальный идентификатор партии                    |
| `player1`        | `Player`                      | Первый игрок                                       |
| `player2`        | `Player`                      | Второй игрок                                       |
| `mode`           | `GameMode`                    | Режим игры (`STANDARD`, `EXPERIENCED`, `EXTENDED`) |
| `board1`         | `Board`                       | Игровое поле первого игрока                        |
| `board2`         | `Board`                       | Игровое поле второго игрока                        |
| `currentPlayer`  | `Player`                      | Игрок, который должен сделать ход в данный момент  |
| `moveHistory`    | `List<Move>`                  | История всех успешно выполненных ходов             |
| `playerAircraft` | `Map<Player, List<Aircraft>>` | Самолёты каждого игрока                            |

**Методы:**

| Метод                                 | Описание                                                                            |
|---------------------------------------|-------------------------------------------------------------------------------------|
| `applyMove(move: Move)`               | Выполняет ход (после валидации), обновляет состояние игры и добавляет ход в историю |
| `isGameOver(): Boolean`               | Возвращает `true`, если все корабли одного из игроков потоплены                     |
| `getWinner(): Player?`                | Возвращает победителя или `null`, если игра не завершена                            |
| `getOpponent(player: Player): Player` | Возвращает соперника указанного игрока                                              |
| `getBoard(player: Player): Board`     | Возвращает поле указанного игрока                                                   |

<hr style="height:10px">

### Класс `Player`
Представляет игрока.

**Поля:**

| Поле     | Тип      | Описание                                          |
|----------|----------|---------------------------------------------------|
| `id`     | `Int`    | Уникальный идентификатор (последовательный номер) |
| `name`   | `String` | Имя игрока                                        |
| `rating` | `Int`    | Текущий рейтинг (изначально 0)                    |

<hr style="height:10px">

### Класс `GameMode <<enumeration>>`
Перечисление режимов игры:
- `STANDARD` – классический режим
- `EXPERIENCED` – количество выстрелов равно числу оставшихся кораблей игрока
- `EXTENDED` – добавлены мины и авиация

<hr style="height:10px">

### Класс `Board`
Игровое поле 10×10 клеток.

**Поля:**

| Поле    | Тип                  | Описание                             |
|---------|----------------------|--------------------------------------|
| `owner` | `Player`             | Владелец поля                        |
| `cells` | `Array<Array<Cell>>` | Матрица 10×10 клеток                 |
| `ships` | `MutableList<Ship>`  | Список кораблей, размещённых на поле |
| `mines` | `MutableList<Mine>`  | Список установленных мин             |

**Методы:**

| Метод                            | Описание                                                         |
|----------------------------------|------------------------------------------------------------------|
| `getCell(x: Int, y: Int): Cell`  | Возвращает клетку по координатам                                 |
| `placeShip(ship: Ship): Boolean` | Проверяет возможность размещения корабля и добавляет его на поле |
| `placeMine(mine: Mine): Boolean` | Проверяет возможность размещения мины и добавляет её на поле     |
| `isAllShipsSunk(): Boolean`      | Проверяет, потоплены ли все корабли                              |
| `getAliveShipsCount(): Int`      | Возвращает количество непотопленных кораблей                     |

<hr style="height:10px">

### Класс `Cell`
Клетка игрового поля.

**Поля:**

| Поле     | Тип         | Описание                 |
|----------|-------------|--------------------------|
| `x`, `y` | `Int`       | Координаты               |
| `state`  | `CellState` | Текущее состояние клетки |

<hr style="height:10px">

### Класс `CellState <<enumeration>>`
Перечисление состояний клеток:
- `EMPTY` – пустая вода
- `SHIP` – неповреждённая палуба корабля
- `HIT` – подбитая палуба
- `MISS` – промах (попадание в пустую клетку)
- `MINED` – заминирована
- `EXPLODED_MINE` – мина взорвана (попадание по мине)

<hr style="height:10px">

### Класс `Ship`
Корабль.

**Поля:**

| Поле    | Тип                 | Описание                    |
|---------|---------------------|-----------------------------|
| `type`  | `ShipType`          | Тип корабля                 |
| `cells` | `MutableList<Cell>` | Клетки, занимаемые кораблём |

**Метод:**
- `isSunk(): Boolean` – возвращает `true`, если все клетки в состоянии `HIT`

<hr style="height:10px">

### Класс `ShipType <<enumeration>>`
Перечисление типов кораблей (по размерам):
- `SINGLE(1)` - 1-палубный катер
- `DOUBLE(2)` - 2-палубный эсминец
- `TRIPLE(3)` - 3-палубный крейсер
- `QUADRUPLE(4)` - 4-палубный линкор

<hr style="height:10px">

### Класс `Mine`
Мина.

**Поля:**

| Поле       | Тип       | Описание                              |
|------------|-----------|---------------------------------------|
| `position` | `Cell`    | Клетка, где установлена мина          |
| `isArmed`  | `Boolean` | Активна ли мина (по умолчанию `true`) |

**Метод:**
- `explode()` – переводит мину в неактивное состояние, меняет состояние своей клетки на `EXPLODED_MINE` и инициирует взрыв симметричной клетки на поле противника

<hr style="height:10px">

### Класс `Aircraft`
Самолёт.

**Поля:**

| Поле            | Тип            | Описание                            |
|-----------------|----------------|-------------------------------------|
| `type`          | `AircraftType` | Тип самолёта                        |
| `owner`         | `Player`       | Владелец                            |
| `remainingUses` | `Int`          | Количество оставшихся использований |

**Метод:**
- `getAttackPattern(anchor: Cell): List<Pair<Int, Int>>` – возвращает список относительных координат атакуемых клеток в зависимости от типа самолёта и якорной точки

<hr style="height:10px">

### Класс `AircraftType <<enumeration>>`

Перечисление типов самолётов:
- `SCOUT` – разведчик (показывает корабли в области 3×3)
- `BOMBER` – бомбардировщик (атакует крестообразную область)
- `TORPEDO` – торпедоносец (атакует всю строку)

<hr style="height:10px">

### Класс `Move`
Абстрактный класс `Move` задаёт общий интерфейс для всех действий игрока.

**Методы:**

| Метод                                | Описание                                            |
|--------------------------------------|-----------------------------------------------------|
| `validate(game: Game): Boolean`      | Проверяет, допустим ли ход в текущем состоянии игры |
| `execute(game: Game)`                | Выполняет ход, изменяя состояние игры               |

### Класс `PlaceMineMove`

**Поле:**
- `mine: Mine` – устанавливаемая мина

### 3.1.2. Движок игры и валидация

### Класс `GameEngine`
Управляет циклом партии.

**Поля:**

| Поле             | Тип             | Описание                                          |
|------------------|-----------------|---------------------------------------------------|
| `currentGame`    | `Game?`         | Текущая активная партия                           |
| `validator`      | `MoveValidator` | Валидатор ходов                                   |
| `shotsRemaining` | `Int`           | Количество оставшихся выстрелов у текущего игрока |

**Методы:**
 
| Метод                                                                  | Описание                                                                                               |
|------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| `startNewGame(player1: Player, player2: Player, mode: GameMode): Game` | Инициализирует новую партию, создаёт доски, устанавливает `RuleSet` и `MoveValidator`                  |
| `processMove(move: Move): MoveResult`                                  | Валидирует ход, выполняет его, обновляет очередь хода и оставшиеся выстрелы, проверяет завершение игры |
| `getShotsRemaining(): Int`                                             | Возвращает оставшиеся выстрелы                                                                         |

<hr style="height:10px">

### Класс `MoveResult <<sealed>>`:
Перечисление вариантов результата хода:
- `Success` – ход успешно выполнен
- `Invalid(reason: String)` – ход не прошёл валидацию
- `GameOver` – игра завершена

Замечание: sealed class, так как enum не смог бы хранить разные виды ошибок для Invalid

<hr style="height:10px">

### Класс `MoveValidator`

**Поле:**
`ruleSet` типа RuleSet - содержит ссылку на текущий `RuleSet`

**Метод:**
`validate(move: Move, game: Game)` - делегирует проверку конкретному ходу и правилам режима

<hr style="height:10px">

### 3.1.3. Правила игры

### Класс `RuleSet`

Интерфейс `RuleSet` инкапсулирует правила, зависящие от режима игры.

**Методы:**

| Метод                                                                   | Описание                                                                        |
|-------------------------------------------------------------------------|---------------------------------------------------------------------------------|
| `getShotsCount(board: Board): Int`                                      | Возвращает количество выстрелов, которое игрок может сделать за свой ход        |
| `canPlaceMine(board: Board): Boolean`                                   | Разрешена ли установка мин                                                      |
| `isValidAircraftTarget(aircraft: Aircraft, cells: List<Cell>): Boolean` | Проверяет, что выбранные клетки соответствуют шаблону атаки самолёта и правилам |

### Реализации интерфейса `RuleSet`:
- **`StandardRules`** – `getShotsCount = 1`, мины и авиация запрещены
- **`ExperiencedRules`** – `getShotsCount = количество живых кораблей игрока`, мины и авиация запрещены
- **`ExtendedRules`** – `getShotsCount = 1`, мины разрешены (до 3), авиация разрешена (до 3 самолётов в сумме)

### Класс `ConsoleUI`
Управление взаимодействием с пользователем.

**Методы:**

| Метод                        | Описание                                                                       |
|------------------------------|--------------------------------------------------------------------------------|

| `finishGame(game: Game)`     | Подведение итогов, обновление рейтингов, сохранение партии                     |
| `managePlayers()`            | Просмотр, добавление игроков                                                   |
| `viewGameLog()`              | Просмотр сохранённого лога по ID                                               |

### Класс `BoardRenderer`
Вспомогательный объект с методом `printBoard(board: Board, hideShips: Boolean)`.

Отображает поле 10×10 в консоли с помощью ASCII‑символов:
- `~` – пустая вода (или скрытый корабль)
- `O` – корабль (только на своём поле)
- `X` – попадание
- `*` – промах
- `M` – мина (на своём поле)
- `!` – взорванная мина

## 4. Взаимодействие компонентов (стандартный сценарий)

1. Пользователь запускает приложение → `ConsoleUI.start()`
2. Выбирает «Новая игра» → `newGame()`:
    - Выбирает двух игроков из списка (или создаёт новых через `PlayerFileData`)
    - Выбирает режим (`GameMode`)
    - Вызывает `engine.startNewGame(...)`, который создаёт объект `Game` и инициализирует `RuleSet` и `MoveValidator`
3. Фаза расстановки (`placementPhase`):
    - Для каждого игрока по очереди запрашивает координаты кораблей и вызывает `board.placeShip()`
    - В режиме `EXTENDED` дополнительно запрашивает установку мин (`board.placeMine()`) и выбор самолётов (заполняется `game.playerAircraft`)
4. Игровой цикл (`gameLoop`):
    - Отображает поле противника (скрытое) и своё поле (открытое) через `BoardRenderer`
    - Запрашивает команду (например, `shot B5` или `scout C3`)
    - Передаёт команду в объект `Move`
    - Вызывает `engine.processMove(move)`
    - `GameEngine` передаёт ход в `MoveValidator`, который проверяет его с учётом текущего `RuleSet`
    - При успехе вызывает `move.execute(game)`, изменяя состояние клеток, кораблей, мин
    - При неудаче возвращает `MoveResult.Invalid` с причиной, UI выводит ошибку и ожидает новый ввод
    - Проверяет условие завершения игры
    - Обновляет очередь хода и оставшиеся выстрелы
5. По окончании игры (`finishGame`):
    - Определяет победителя
    - Обновляет рейтинги через `PlayerFileData.updateRating()`
    - Сохраняет партию через `GameFileData.saveGame()`
    - Выводит результат

## 6. Хранение данных
Все данные хранятся в текстовых файлах в рабочей директории приложения:

- `players.txt` – список игроков
- `games.txt` – краткая сводка завершённых партий
- `logs/game_<id>.txt` – полные журналы партий
